# Session 08 — One live provider adapter and explicit offline test double

## Goal
Add one Anthropic Messages/tool adapter and a named `ScriptedProvider` test
double. Upgrade live preflight to a one-tool smoke test. Do not build the
investigation loop.

## Completed changes
- `Provider.generate(system_prompt, messages, tool_definitions, settings, *, remaining_seconds=None, tool_choice=None) -> ProviderTurn`
  sends tools, returns normalized `ToolCall`s, public text, stop reason, usage,
  and the opaque assistant message (tool-use blocks preserved).
- `AnthropicProvider` uses the official SDK with `max_retries=0`, no
  temperature/thinking/cache_control, timeout capped to remaining case time,
  and at most one retry for rate-limit/server/connection errors. A long
  `Retry-After` that cannot fit the remaining budget stops with
  `PROVIDER_RATE_LIMIT`. Auth/permission/schema failures are not retried.
- `ScriptedProvider` yields explicit `ProviderTurn`/`ProviderError` sequences.
  `select_provider(..., scripted=)` refuses that class when `enable_live` is
  true.
- `tool_result_user_message` formats Anthropic `tool_result` blocks with the
  original call IDs; errors set `is_error`.
- `precedent preflight --live` now requires a `preflight_ping` tool call
  through the adapter. It still refuses unless live mode, key, and model are
  configured, and it never prints secrets.
