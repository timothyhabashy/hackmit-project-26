# Session 09 — Bounded investigation agent

## Goal
Add the multi-turn investigation loop: inspect a case through tools, validate
or request review, terminate at a documented state, and expose `precedent run`.
Do not build learned memory or weaken validation.

## Completed changes
- `services.investigate(settings, workspace_id, case_id, *, mode, memory_mode)
  -> RunResult` opens a fresh connection and calls `investigate_case`.
- The loop uses Session 08 `Provider.generate`, Session 07 `dispatch_tool`,
  and `tool_result_user_message`. It does not hardcode transfer references or
  action order. Context is host-bound.
- Budgets: model requests, tool calls, and elapsed case time. Exhaustion is
  `ERROR/BUDGET_EXHAUSTED`, never a business review. One text-only reminder is
  allowed; a second empty turn is `ERROR/NO_TERMINAL_ACTION`.
- After a successful `submit_resolution` or `request_review`, remaining
  same-turn calls are skipped with `TERMINAL_REACHED` and still return a
  `tool_result` for every `tool_use` id. No further provider request is made.
- Interrupted `RUNNING` cases are reconciled to `ERROR/INTERRUPTED` before a
  new run. `RESOLVED` cases cannot be rerun on the same ledger.
- `precedent run --workspace ID --case ID --memory off|on --live` prints
  outcome, usage, and trace. `--live` is required and never selects
  `ScriptedProvider`. Exit 0 includes a completed `REVIEW`.

T03 IDs used in scripted tests: case `CASE-1CFA9FEE848F`, payment `PAY-201`,
remittance `DOC-R201`, fee notice `DOC-F201`, invoice `INV-1042`.

## Investigation API for Session 10
```text
investigate(settings, workspace_id, case_id, *, mode, memory_mode,
            provider=None, run_id=None) -> RunResult
investigate_case(connection, settings, workspace_id, case_id, *, mode,
                 memory_mode, provider=None, run_id=None) -> RunResult
InvestigationError(code, message)  # before a run starts
precedent run --workspace ID --case ID --memory off --live
```
- Route UI/CLI investigation through `services.investigate`.
- `memory_mode=off` uses `empty_memory_snapshot()`. `on` is accepted but still
  empty until Session 12.
- Terminal tools remain `submit_resolution` and `request_review`.
