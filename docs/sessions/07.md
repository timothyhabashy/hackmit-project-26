# Session 07 — Typed agent tool registry and trace events

## Goal
Expose only the F2 investigator tools through a typed registry, bind
run/workspace/case outside model arguments, and persist observable traces
without shell, SQL, filesystem, or grading access.

## Completed changes
- `precedent.tools.dispatch_tool` validates `extra=forbid` arguments and
  dispatches `get_case`, `search_invoices`, `search_documents`,
  `read_document`, `retrieve_precedents`, `validate_resolution`,
  `submit_resolution`, and `request_review`.
- Host `RunContext` supplies workspace/run/company. Model arguments cannot
  set `workspace_id`, `db_path`, or filesystem paths. Unknown tools and
  extra/invalid parameters return `UNKNOWN_TOOL` or `INVALID_TOOL_ARGUMENTS`.
- `validate_resolution` calls `store_proposal` (D004) and does not apply.
  `submit_resolution` calls `apply_proposal` with host key `submit:{id}`.
  `request_review` writes `NEEDS_REVIEW` with no financial mutation.
  `INVALID_SCHEMA` and `WRONG_WORKSPACE` cannot satisfy a business review.
- `retrieve_precedents` requires an opened payment-bound remittance. Empty
  `MemorySnapshot` is the ordinary pre-learning baseline. Scope uses confirmed
  customer plus current payment account/currency/channel. Conflicting
  remittances return `CONFLICTING_EVIDENCE` and no hints.
- Traces record `run_started`, `tool_called`, `tool_succeeded`/`tool_failed`,
  `proposal_validated`/`proposal_rejected`, `precedent_retrieved`,
  `application_committed` (from apply), `review_requested`, and `run_finished`.
  Secrets are redacted. Source instruction text cannot add a tool.
- `src/precedent/prompts/investigator.md` covers F3 without fixture IDs.
