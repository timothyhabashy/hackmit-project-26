# Session 03 — Concrete synthetic cases and isolated answer keys

## Goal
Create exactly 35 deterministic synthetic case packages, store expected
decisions under `data/grading/`, and add `demo init` / `demo new` helpers
that import a split into a new sandbox workspace without deleting reports.

## Completed changes
- `src/precedent/fixtures.py` generates 10 teaching, 5 candidate-development,
  and 20 held-out packages from seed `42`. Runtime directories are neutral
  `CASE-*` IDs. Authoring IDs T/V/H exist only in grading/manifests.
- T03 uses the Section N source IDs and document bodies (`INV-1042`,
  `PAY-201`, `DOC-R201`, `DOC-F201`, `ST-8721`) plus distractors.
- Isolated `OracleRecord` JSON under `data/grading/` specifies allocations,
  ending balances, application counts, and allowed review codes. Cedar
  controls list Harbor's wire-fee scope as forbidden.
- `precedent fixtures build --seed 42` writes source/grading/manifest trees.
- `precedent.services.demo_init` / `demo_new` import a split into SQLite.
  Seeded already-applied payments keep opening balances and `seeded=true`
  applications. A second init creates `WS-TEACH-002` and leaves the first
  workspace and evaluation_runs rows in place.
- `insert_application` can join an open transaction so workspace import is
  atomic.
