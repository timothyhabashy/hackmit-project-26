# Session 04 — Evidence search and retrieval

## Goal
Add workspace-scoped invoice/document lookup and `read_document` so T03 can
be followed from payment advice to the bank fee notice, without exposing
`data/grading` or treating a search hit as opened evidence.

## Completed changes
- `precedent.evidence` implements `search_invoices`, `search_documents`, and
  `read_document`. Arguments match F2 (`extra=forbid`). Host `RunContext`
  supplies workspace/company; callers cannot pass a DB or filesystem path.
- Structured filters are exact after trim. `query` is case-insensitive
  whitespace-token substring search over IDs, customer, currency, dates,
  status, titles, and document bodies. Amount fields are not searchable.
- Document hits return ID, kind, title, issued date, snippet, and sha256.
  Facts are returned only from `read_document`, which records
  `OpenedEvidence` on the current run.
- Empty searches return `ok=true` with `hits=[]`. Missing reads return
  `NOT_FOUND`. Path-like IDs and extra arguments return
  `INVALID_TOOL_ARGUMENTS`. Cross-workspace IDs do not resolve.
- `precedent.db` gained ordered `list_invoices` / `list_documents`.

T03 demonstration (isolated temp workspace, not grading): payment `PAY-201`
(`BR-201`, 996500) → remittance search `DOC-R201` (not opened) → read
`settlement_ticket=ST-8721` → fee notice `DOC-F201` (`fee_cents=3500`).
Harbor invoices: `INV-1042`. Cedar invoices: `INV-5BD2CDB765F9`. Cedar +
`ST-8721` returned no hits. `builtins.open` saw no `grading` paths.
