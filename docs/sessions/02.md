# Session 02 — Canonical domain models and persistence

## Goal
Add typed Pydantic domain models and a SQLite schema for runtime source
records, investigations, proposals, ledger applications, corrections, lessons,
and evaluation metadata. Integer cents, explicit currencies, workspace-scoped
IDs. No importer, validator, UI, or migration framework.

## Completed changes
- `src/precedent/models.py`: source and persisted models, E4/F5 enums, G2 hint
  template, Pydantic response shapes from section P, canonical JSON/SHA-256
  helpers, and `parse_cents` for CSV whole-number strings.
- `src/precedent/db.py`: `PRAGMA foreign_keys=ON`, busy timeout 5000 ms,
  `schema_version=1` tables, transactions (`BEGIN` / `BEGIN IMMEDIATE`), and
  typed insert/get helpers. Duplicate application identity, payment, and
  idempotency key fail at storage.
- Invoice current outstanding is stored separately from opening/source
  balances. Payments store `applied` separately from source fields.
- EUR and other well-formed currencies are importable; malformed codes and
  non-strict money fail model/schema checks.
- `Settings.anthropic_api_key` is excluded from `repr` (section P).

Callable persistence interface for later sessions:

`connect`, `initialize_schema`, `open_database`, `transaction`,
`PersistenceError`, `insert_workspace`/`get_workspace`,
`insert_customer`/`get_customer`, `insert_invoice`/`get_invoice`,
`insert_payment`/`get_payment`, `insert_document`/`get_document`,
`insert_case`/`get_case`, `insert_application`/`get_application`.
