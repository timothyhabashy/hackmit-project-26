## Goal
Run five candidate-development cases twice each in isolated sandboxes,
score observed outcomes with evaluator-only oracles, and activate only a
compatible LIVE passing version after explicit approval. Do not load
persisted memory for ordinary runs.

## Completed changes
- Isolated executor/scorer live in `evaluation.py`. Oracles load after the
  run and never enter `RunContext`. Candidate injection is an explicit
  `MemorySnapshot` on `investigate_case`; Session 12 still owns production
  loading.
- Paired suite: V01–V05, empty baseline vs one candidate snapshot, arm
  order by case index. Episodes import into `WS-CTEST-*` workspaces in the
  same SQLite file and do not mutate the owner ledger.
- Lifecycle: `DRAFT → TESTING → PASSED/FAILED`, then explicit approval to
  `ACTIVE` or `REJECTED`; `ACTIVE` may become `RETIRED`. `redraft` is the
  only refresh path and inherits no report or approval.
- Activation requires `PASSED`, matching payload/policy/dev-suite/
  fingerprint hashes, validator/lifecycle checks, actor
  `demo_controller`, and a LIVE report. TEST reports are refused:
  "offline scripted checks cannot authorize a live-tested lesson."
- Schema rejects threshold/write-off extras. A scripted fee on the V02
  dispute gap fails the suite. Harbor scope is never returned for V03.
- CLI: `precedent lesson test --id ID --live`, `activate`, `retire`,
  `redraft`. `--live` never selects `ScriptedProvider`. FAILED reports
  exit 1; live-disabled/invalid input exit 2.
