# Session 06 — Atomic sandbox application and fresh-workspace reset

## Goal
Apply a stored proposal inside one immediate SQLite transaction, revalidating
current state, writing application/allocations once, and resetting only by
creating a new sandbox workspace.

## Completed changes
- `apply_proposal(repo, context, proposal_id, *, idempotency_key, actor)` starts
  `BEGIN IMMEDIATE`, hashes the stored payload, then checks the operation key
  before current-state validation.
- Same key and same payload returns `REPLAYED` even when
  `context.initial_ledger_revision` is now stale. Same key and a different
  payload returns `IDEMPOTENCY_CONFLICT`. A different key against an applied
  payment returns `PAYMENT_ALREADY_APPLIED`. Those retries write zero new
  financial rows.
- A new operation revalidates inside the transaction. Stale revision returns
  `STALE_LEDGER`. A valid apply decrements invoices by cash+fee, marks the
  payment applied, increments `ledger_revision`, stores a non-seeded
  application, sets the case `RESOLVED`, and records `APPLICATION_COMMITTED`.
- Injected failure after the first T02 allocation rolls back all writes.
- `store_proposal` persists a schema-valid proposal (D004). `get_case_snapshot`
  returns payment, policy, revision, and remittance-related invoices.
- `snapshot_case` and `apply_stored_proposal` open a fresh connection.
  `demo_new` still creates a new workspace and does not delete reports or
  mutate another workspace's ledger. Seeded T10 history is not subtracted again.

T03 (`CASE-1CFA9FEE848F`, `PAY-201`, `INV-1042`, `DOC-R201`, `DOC-F201`):
apply cash 996500 / fee 3500 once; `INV-1042` outstanding 0 (opening 1000000);
`PAY-201` applied; revision 1. Replay of `APPLY-T03` with stale revision 0
returns `REPLAYED` with the same application ID. Conflicting payload on that
key is `IDEMPOTENCY_CONFLICT`. A second key is `PAYMENT_ALREADY_APPLIED`.
Application count stays 1.

T02 bundle: Harbor invoices stay at 65000 and 35000 after injected rollback
(revision 0, applications 0). A later successful apply zeros both invoices.
